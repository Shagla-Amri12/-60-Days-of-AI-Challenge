Architecture overview

The pipeline runs seven specialized agents against the live Claude API. Planner and Executor run once to produce a first draft. The loop — Evaluator → Critic → Improver — then repeats, with the Memory Manager threading forward a running note of recurring issues so the Improver doesn't regress. Every round is checked against three stop conditions in order: score threshold, plateau (score gain < 2 for two straight rounds), then a hard iteration cap as a safety fallback. Once a stop condition fires, control branches to the Final Reviewer, which never participates in the loop itself. A Safety Monitor screens the first draft once for unsafe code patterns.

Extension ideas

Parallel criticsRun 2–3 Critic personas (security, performance, style) concurrently and merge findings before the Improver pass.
Tool-using ExecutorLet the Executor call a sandboxed code-runner tool to actually execute tests and feed real failures to the Evaluator.
Human-in-the-loop gatePause before the Final Reviewer and let a person approve, edit the critique, or force another round.
Multi-file scopeGeneralize Planner output to a file tree, and run the loop per-file with a cross-file consistency check before final review.

Prompts for building more advanced autonomous systems

Add branching plans"Modify the Planner to output 2 candidate approaches, and have the Evaluator score both before Executor commits to one."
Persistent memory"Give the Memory Manager a running JSON store of lessons learned across multiple pipeline runs, not just within one."
Cost-aware stopping"Add a fourth stop condition based on cumulative token spend, surfaced next to the plateau/threshold/cap reasons."
Adversarial safety loop"Turn the Safety Monitor into a repeating agent that re-runs after every Improver pass, not just once on the first draft."
