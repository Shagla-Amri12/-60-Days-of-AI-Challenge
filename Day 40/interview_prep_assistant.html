How this was built

System prompt design

The assistant's "brain" is a single system prompt that fixes it into one role: a friendly, encouraging senior interviewer conducting a realistic mock interview for the role and level the candidate describes. It's told explicitly to ask one question at a time, tailor questions to the pasted role/JD (mixing behavioral and role-specific technical questions), keep acknowledgments brief so the candidate does most of the talking, and never break character mid-interview. A hard structural rule — reply only with the next question, nothing else, until told the interview is ending — keeps the conversation predictable enough for the UI to render as a clean chat.

For the final turn, the same prompt switches modes: it's instructed to synthesize the whole transcript into strict JSON (score out of 100, verdict line, 3–5 strengths, 3–5 growth areas, and per-question feedback) so the app can render it as a structured report instead of more chat text. Edge cases are handled directly in the prompt: vague or off-topic role descriptions get a best-effort interpretation rather than a refusal; very short or empty candidate answers are noted as a weakness instead of causing the interviewer to stall; and the model is told to never fabricate praise it can't back up with something the candidate actually said.

UI decisions

The interface is built around a "green room" metaphor — the quiet space before you go on stage — rather than a generic chatbot shell, to keep the tone calm and encouraging instead of clinical. Three screens map to the natural arc of a real interview: setup (waiting room), a chat-style live interview with a visible progress ladder so nerves have something concrete to track, and a report screen styled like a printed evaluation sheet with a large score, a verdict pill, and separate strength/growth columns so feedback reads as coaching, not just a grade.

Motion is deliberately restrained: messages rise in gently, a three-dot typing indicator stands in for the interviewer "thinking," and the progress rungs fill in amber as questions are answered — everything else stays still so the one signature element (the ladder) carries the pacing cue.

Ideas for future extensions

Tools: connect a resume-parsing step (PDF upload) so questions are grounded in the candidate's actual experience, not just their self-description; add a web-search tool so the interviewer can reference realistic, current interview questions for a specific company.

Memory: persist past sessions (with the user's consent, in real backend storage rather than browser storage) so the coach can track score trends across multiple mock interviews and target previously weak areas first.

Multi-step workflows: branch into a two-stage flow — a resume/JD gap analysis before the interview even starts, then a follow-up "rewrite this answer with me" coaching turn after the report, so the report becomes a starting point for iteration rather than a dead end.
